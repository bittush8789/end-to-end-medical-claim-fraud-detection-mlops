# High‑Level System Design – Medical Claim Fraud Detection

> **Goal:** Provide a concise, top‑level view of the end‑to‑end MLOps architecture for the application.

---

## 1. Overview
The system ingests raw medical claim data, processes it, trains a fraud‑detection model, registers the model in DVC, containerises the inference service, and deploys it on Kubernetes with KServe. A FastAPI backend exposes the model to a modern HTML/CSS/JS frontend. CI/CD automates the entire flow using GitHub Actions, Helm, and ArgoCD, while Prometheus + Grafana provide observability.

## 4. Deployment Flow (Simplified)
1. **Push** code → GitHub Action `setup‑infra` creates a Kind cluster & installs monitoring tools.
2. **Build** job runs the pipeline, builds the Docker image, and updates Helm `values.yaml`.
3. **Commit** changes → ArgoCD detects Helm update and applies it to the target Kubernetes cluster.
4. **KServe** pulls the model from the Docker image and serves it.
5. **FastAPI** receives user requests, calls KServe, returns predictions.
6. **Prometheus/Grafana** continuously monitor service health and model performance.

---

## 5. Security & Secrets
- All sensitive values (AWS keys, Docker Hub credentials) are stored as **GitHub Secrets** and injected into the workflow.
- FastAPI is exposed behind an **Ingress** with optional TLS.
- KServe pods are isolated via **NetworkPolicies** – only FastAPI can reach them.
- DVC remote uses an S3 bucket with least‑privilege IAM policies.
